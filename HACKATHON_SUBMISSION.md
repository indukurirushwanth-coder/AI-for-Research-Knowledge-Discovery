# 🏆 Hackathon Submission: ResearchLens AI
**Theme**: AI for Research & Knowledge Discovery  
**Project Name**: ResearchLens AI  
**Repository**: `researchlens-ai`

---

## 1. Problem Statement

Modern scientific literature is expanding at an unprecedented rate, with over 3 million research articles published annually. Researchers, clinicians, students, and intelligence analysts face severe bottlenecks:

- **Time Poverty**: Synthesizing findings across 5–10 papers in a new domain takes days of fragmented reading.
- **Hallucination Risk**: General-purpose LLMs frequently invent citations, misattribute quotes, and blur distinct paper conclusions into ungrounded summaries.
- **Divergence Blindness**: Traditional search engines retrieve documents individually without revealing whether Paper A's empirical findings contradict or confirm Paper B's conclusions.
- **Unverifiable Claims**: Chat-with-PDF tools often return monolithic answers without linking each factual assertion to the exact document and physical page number where it originated.

Researchers need an objective, evidence-grounded research partner that answers only from what the text states, admits when evidence is absent, and structures cross-paper comparisons with verified citations.

---

## 2. Solution Description

**ResearchLens AI** is a production-minded web platform designed for evidence-grounded multi-paper analysis and knowledge discovery.

Instead of treating PDFs as decorative file attachments, ResearchLens AI decomposes each research document into physical page units, generates overlapping semantic chunks, and applies a deterministic BM25 retrieval engine before invoking Google Gemini.

Key capabilities:
1. **Multi-PDF Vault**: Ingests multiple research papers, validates file integrity, extracts text page-by-page, and stores searchable chunks with page metadata.
2. **Evidence-Grounded Research Inquiries**: Answers user questions strictly using retrieved excerpts. Every claim is cited with explicit source tags (`[Source 1]`, `[Source 2]`) mapping to physical page numbers and document titles.
3. **Hallucination Resistance & Insufficient Evidence Handling**: When an inquiry asks about concepts not substantiated in the uploaded papers, the system explicitly reports that evidence is insufficient rather than guessing.
4. **Cross-Paper Comparative Analysis**: Compares two or more papers side-by-side, analyzing Objectives, Methodologies, Empirical Findings, Limitations, and Conclusions. It highlights verified Convergences (Agreements) and empirical Divergences (Disagreements).
5. **Knowledge Discovery**: Synthesizes recurring themes across the document collection and identifies research gaps for follow-up empirical investigation.

## 3. AI Integration & Key Features

### Official Google Gemini SDK Integration
- Integrated via the official `@google/genai` JavaScript SDK (`v2.28+`).
- Configurable model endpoint defaulting to `gemini-2.5-flash` for high throughput, grounded reasoning, and low latency.
- API keys are strictly guarded in backend environment variables and are never transmitted to client browsers or exposed in logs.

### Retrieval-Augmented Grounding Architecture
```
[User Inquiry] 
      │
      ▼
[BM25 / TF-IDF Retrieval Filter]  ──► (Ranks chunks across user's papers)
      │
      ▼  (Top-K relevant passages with [Source N] tags & page numbers)
[Google Gemini 2.5 Flash]        ──► (Strict system prompt: Grounded synthesis only)
      │
      ▼
[JSON Citation Validation]       ──► (Verifies [Source N] tags against retrieved chunks)
      │
      ▼
[Interactive UI Answer & Evidence Cards]
```

### Citation Integrity & Trust
- Citations generated by the model are parsed and cross-checked against actual retrieved passages.
- Only verified passages are rendered as interactive Evidence Cards.
- Clicking an inline `[Source N]` badge in the answer smoothly scrolls and highlights the underlying source excerpt with its page badge.

## 4. Technology Stack

### Frontend
- **Framework**: React 19 + Vite 8
- **Routing**: React Router DOM v7
- **Styling**: Tailwind CSS v4 (Modern academic dark theme with Navy/Indigo palette)
- **API Client**: Axios with automatic JWT interceptors and session refresh handling
- **Icons**: Lucide React

### Backend
- **Runtime**: Node.js v20+ / v26+ (ES Modules)
- **Framework**: Express.js v4
- **AI SDK**: `@google/genai` (Official Google Gemini SDK)
- **PDF Extraction**: `pdfjs-dist` (Mozilla PDF engine preserving exact physical page indices)
- **Security**: `helmet`, `cors`, `bcryptjs` password hashing, `jsonwebtoken`, `zod` input validation, and `multer` in-memory buffering.

### Database
- **Primary**: Supabase PostgreSQL with parameterized queries, indexes on full-text search and document ownership, and foreign key cascading.
- **Development Fallback**: Embedded persistent local store ensuring zero friction for evaluators who want to test the entire application locally without provisioning Supabase.

---

## 5. Innovation & Real-World Impact

1. **Academic Rigor Over Generative Hype**:
   While most AI tools prioritize verbose text generation, ResearchLens AI prioritizes **falsifiability**. Every synthesized assertion is tied to a specific page number.

2. **Cross-Paper Divergence Detection**:
   Single-document chat tools cannot spot contradictions. ResearchLens AI simultaneously indexes multiple papers and highlights where authors reach conflicting conclusions (e.g., whether lattice-based cryptography is viable on low-power IoT devices).

3. **Production-Grade User Isolation**:
   Document ownership is strictly verified on every query and deletion operation. Users cannot inspect or query another researcher's confidential pre-prints.

4. **Zero-Friction Evaluation**:
   Includes 1-click sample paper loading directly in the UI, allowing hackathon judges to test multi-paper ingestion, grounded Q&A, and paper comparison in under 60 seconds without searching for PDFs.

---

## 6. Current Limitations & Future Scope

### Current Limitations:
- **Scanned Image PDFs**: ResearchLens AI processes selectable text. Scanned paper archives requiring OCR need optical character recognition preprocessing before ingestion.
- **Single-Language Focus**: The BM25 tokenizer is tuned for English-language scientific terminology.

### Future Scope:
- **Multimodal Chart & Figure Analysis**: Leverage Gemini 2.5 Flash multimodal capabilities to parse data figures, spectra, and chemical structures embedded in PDFs.
- **Semantic Vector Hybrid Search**: Integrate Supabase `pgvector` with Google text-embedding models for hybrid dense-sparse retrieval.
- **BibTeX & Zotero Export**: One-click citation export to reference managers.
